Command line

usage
cytoweave [flags] [FCS files, folders, workspaces (.cwz), Gating-ML or FlowJo .wsp files...]
cytoweave mcp [flags]
FlagDefaultEffect
--window app|browser|noneappOpen an app window (Chrome, Edge, Brave or Chromium, with its own profile), the default browser, or nothing
--no-openSame as --window none
--keep-runningKeep serving after the window is closed
--port8770Preferred port; the next free one is used if it is taken
--host127.0.0.1Interface to bind. Keep the default unless you mean to serve other machines (for example 0.0.0.0 on a trusted network), which turns off the DNS-rebinding check
--data-diruser config dirFolder of the workspace library
--no-libraryKeep workspaces in the browser's own storage instead
--remote-controlAccept actions from programs on this computer (below)
--devServe web/ from the working directory (for development)
--versionPrint the version

CytoWeave prints the address it serves, for example http://127.0.0.1:8770. With --window none, open that address in any browser yourself. Files named when CytoWeave is already running are handed to the open window.

Remote control from your programs

cytoweave --remote-control accepts the actions of the MCP tools from programs on this computer, as JSON posted to /api/remote/action. The window must be open: it performs each action with the same code as the user interface, so you watch the script work.

$ cytoweave --remote-control
python
import requests

URL = "http://127.0.0.1:8770/api/remote/action"

def act(action, client="Plate pipeline", **args):
    reply = requests.post(URL, json={"action": action, "args": args, "client": client}).json()
    if not reply.get("ok"):
        raise RuntimeError(reply.get("message") or reply.get("error"))
    return reply

act("open_example", id="pbmc-immunophenotyping")
act("auto_gate", method="singlets", x="FSC-A", y="FSC-H", name="Single cells")
print(act("list_populations")["message"])
for row in act("statistics_table", statistic="freqParent")["data"]["rows"]:
    print(row["sample"], row["meta"].get("condition"), row["values"])

Every reply has ok, a plain-language message and the data. Each request is {"action": …, "args": {…}, "client": …}. A script's changes are proposals too, shown in the window under the name it gives in client, for you to accept or reject. Actions reach the window one at a time.

Opening files by path

open_files makes the program read files from disk, so it also needs the X-CytoWeave-Token header with the token CytoWeave prints when it starts:

python
TOKEN = "…"  # printed by cytoweave --remote-control
requests.post(URL, headers={"X-CytoWeave-Token": TOKEN},
              json={"action": "open_files", "args": {"paths": ["/data/2026-09-30_panel1/"]}})

Paths must be absolute. Each folder becomes a sample group.

What scripts are good for

  • Batch runs: open each day's plate, apply the lab's gating strategy, review the gates across samples, and write the statistics table to a file.
  • Notebooks: pull statistics_table results into pandas, next to the plots CytoWeave renders with render_plot.
  • Pipelines: keep the analysis visible and reviewable in the window while a program does the repetitive part.

The arguments of every action are those of the MCP tools; docs/MCP.md lists them, with the coordinate conventions for each gate type.

Security

Remote control is off unless you start CytoWeave with --remote-control (cytoweave mcp turns it on for its own session). The server accepts actions only from this computer, and actions that read files from disk need the per-session token. Leave --host at its default while remote control is on.
