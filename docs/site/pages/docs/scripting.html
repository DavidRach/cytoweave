cytoweave mcp [flags]
FlagDefaultEffect

--versionPrint the version

CytoWeave prints the address it serves, for example http://127.0.0.1:8770. With --window none, open that address in any browser yourself. Files named when CytoWeave is already running are handed to the open window.

Remote control from your programs

cytoweave --remote-control accepts the actions of the MCP tools from programs on this computer. The window must be open: it performs each action with the same code as the user interface, so you watch the script work. A script's changes are proposals too, shown in the window under the script's name, for you to accept or reject. Actions reach the window one at a time.

$ cytoweave --remote-control

The R and Python clients

The clients in clients/ make every action a function, with its arguments and help, and find the running CytoWeave themselves. They are installed from the repository (they are not on CRAN or PyPI):

R
remotes::install_github("robert-mcdermott/cytoweave", subdir = "clients/r")
shell
$ pip install "git+https://github.com/robert-mcdermott/cytoweave#subdirectory=clients/python"
R
library(cytoweave)
cw_connect()                                  # finds the running CytoWeave
cw_open_files(c("/data/2026-09-30_panel1/"))  # each folder becomes a group
cw_auto_gate(method = "singlets", x = "FSC-A", y = "FSC-H", name = "Single cells")
frequencies <- as.data.frame(cw_statistics_table(statistic = "freqParent"))
states <- cw_differential_analysis("condition", groups = c("Unstimulated", "Stimulated"),
                                   pair_by = "subject", clusters = "FlowSOM cluster")
as.data.frame(states)                         # marker by cluster, lowest p first
python
import cytoweave

cw = cytoweave.connect()                      # finds the running CytoWeave
cw.open_example(id="pbmc-immunophenotyping")
print(cw.list_populations().message)
table = cw.statistics_table(statistic="freqParent").frame()   # a pandas DataFrame
cw.render_plot("CD3", population="T cells", file="t-cells.png")
cw.export_table("/tmp/frequencies.xlsx", statistic="freqParent")

Arguments are those of the MCP tools in snake case (group_by, pair_by); each function's help (?cw_differential_analysis, help(cw.differential_analysis)) lists them. Every result has the action's message and its data; as.data.frame() in R and .frame() in Python (with pandas) turn the table in it into a data frame. An action CytoWeave refuses is an error with its reason. cw_call() and cw.call() send any action by its name, and cw_tools() and cw.tools() list them.

Without arguments, the clients connect through the remote.json file CytoWeave writes to its data folder when remote control is on: its address and token, readable by you only, removed when CytoWeave stops. Give the address and token yourself, or set CYTOWEAVE_URL and CYTOWEAVE_TOKEN, or CYTOWEAVE_DATA_DIR when CytoWeave runs with --data-dir. The clients' version is CytoWeave's, and each release's clients are tested against that release.

Any language: JSON over HTTP

Each action is JSON posted to /api/remote/action, as {"action": …, "args": {…}, "client": …}; every reply has ok, a plain-language message and the data. GET /api/remote/tools lists the actions with their arguments.

python
import requests

URL = "http://127.0.0.1:8770/api/remote/action"

def act(action, client="Plate pipeline", **args):
    reply = requests.post(URL, json={"action": action, "args": args, "client": client}).json()
    if not reply.get("ok"):
        raise RuntimeError(reply.get("message") or reply.get("error"))
    return reply

act("open_example", id="pbmc-immunophenotyping")
act("auto_gate", method="singlets", x="FSC-A", y="FSC-H", name="Single cells")
print(act("list_populations")["message"])
for row in act("statistics_table", statistic="freqParent")["data"]["rows"]:
    print(row["sample"], row["meta"].get("condition"), row["values"])

Opening and writing files

open_files and the export actions make the program read or write files, so they also need the X-CytoWeave-Token header with the token CytoWeave prints when it starts (the clients send it):

python
TOKEN = "…"  # printed by cytoweave --remote-control, and in remote.json
requests.post(URL, headers={"X-CytoWeave-Token": TOKEN},
              json={"action": "open_files", "args": {"paths": ["/data/2026-09-30_panel1/"]}})

Paths must be absolute. Each folder becomes a sample group. Exports go only to the path given, in a folder that exists, and never replace a file unless overwrite is given.

What scripts are good for

  • Batch runs: open each day's plate, apply the lab's gating strategy, review the gates across samples, and write the statistics table to a file.
  • Notebooks: pull statistics_table and differential_analysis results into R or pandas, next to the plots CytoWeave renders with render_plot.
  • Pipelines: keep the analysis visible and reviewable in the window while a program does the repetitive part.

The arguments of every action are those of the MCP tools; docs/MCP.md lists them, with the coordinate conventions for each gate type.

Security

Remote control is off unless you start CytoWeave with --remote-control (cytoweave mcp turns it on for its own session). The server accepts actions only from this computer, and actions that read or write files need the per-session token, which only you can read in remote.json. Leave --host at its default while remote control is on.
